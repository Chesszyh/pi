*一位非工程师的笔记*

我不是工程师。在一家为那些对着黑色终端窗口敲命令的程序员开发 agent harness 软件的公司里，这件事以前总让我觉得应该压低声音说。身边的每个人都在交付代码。我在写文档、做规划、和人沟通。这些工作当然有用，但我其实并没有真正使用我们自己做的东西。

所以有一阵子，我也做了许多人面对 AI 时会默默做的事：跟着点头。我听“agent”“loop”“harness”“extension”这些词听得够多了，于是在会议里已经能点头点得很像那么回事。别人都觉得 TUI（Terminal User Interface，终端用户界面）理所当然时，我偷偷去 Google 它到底是什么。等我终于弄明白，他们已经开始聊 API 了，而我又回到了原点。借用我们自己那篇 [What is a Harness?](https://earendil.com/posts/what-is-a-harness/) 里的说法，我就是那个“因为太不好意思，所以不敢问”的人。

后来我不再只是跟着点头，而是做了一件更好的事：我打开 Pi，直接开始问。

Harness 并不在乎你会不会写代码。你打开它，用自然语言输入自己想要什么，它就开始工作。我原本以为总会到某一步，因为自己懂得不够而卡住。结果并没有，我只需要继续把自己想要的东西说出来。第一次，我让它读一份又长又难看的 PDF，然后告诉我其中真正需要知道的三件事，它就直接做完了。我当时产生了一种小小的、甚至有点可笑的力量感。

在那层看起来吓人的外壳下面，harness 其实就是一种工具：把“真希望有人替我把这件事做了”变成“做完了”。

**把它变成我的**<br>
Pi 最让我喜欢的一项用途其实和软件毫无关系。每天早上，它会通读我的收件箱和会议笔记，找出我真正答应过别人要做的事情，然后给我生成一份干净的待办列表：一组是我欠别人的事项，一组是我正在等别人完成的事项。我没有雇任何人，也没有去学写代码。我只描述过一次这份工作，现在它就成了一个在我机器上运行的小例程，形状完全贴合我的思维方式。

有时候好奇心上来，我想看看引擎盖下面是什么，Pi 又会变成一个耐心得惊人的老师。有一次，我让它带着我写一个 Google Apps Script。它一步一步把整个过程带我走完，就像你去请团队里最愿意帮助人的 SWE（Software Engineer，软件工程师）同事解释一个东西：用普通语言讲清楚，而且不会让你觉得自己很蠢。就在那种解释进行到某个地方时，代码突然不再那么令人畏惧。现在我也会自己做东西了。没有什么突破性的成果，大多只是一些确实让我的工作和生活更轻松的小工具：从制作个性化电子邀请函，到管理邮件互动指标，再到用电子表格自动化整理数据。

也就是那时，我终于真正理解了那句标语：Agent harness 有很多，但这个是你的。以前我觉得这是写给工程师的——那些会掀开引擎盖、重新接线的人。现在我对“你的”有了另一种理解。它并不是说这东西必须由你亲手造出来，而是说：无论你是谁，你都可以把它弯折成适合自己生活的形状。

我把自己的 Pi 围绕一个乱七八糟的收件箱塑造成形。另一个人也许会围绕课程计划、研究工作，或者小企业记账去塑造它。

**为什么这件事比我的待办列表更重要**<br>
Pi 免费、开源，而且运行在我自己的笔记本电脑上。以前这些在我听来只是技术说明里的脚注。现在我明白它为什么重要：我可以把它塑造成适合自己工作方式的样子。真正让我感到不同的一点，是 Pi 能够查看自己的代码、解释自己是怎么工作的，然后帮助我修改它。就好像这个工具还能教我怎样重新打造工具本身。Pi 用户已经彼此分享了超过 5,000 个扩展，把他们为自己构建的工作流免费提供给其他人。

关于 AI 的大部分讨论，都集中在这项技术会“对我们做什么”。从我所处的位置看，更有意思的事情在于：我不再需要等某个懂技术的人替我把自己需要的东西做出来。

我仍然不是工程师。但我已经不再小声说这件事。事实证明，想真正拥有自己的工具，并不要求你先成为工程师；你只需要有足够的好奇心去提问，也有足够的勇气继续问下去。

Jakob，Earendil Founders Associate（创始人办公室成员）
